- The gate reads more forms of a write, wherever it lands (spec §12.6, §20.2): `sed -i.bak` and BSD's `sed -I`, and a
  script attached (`sed -i -es/a/b/ f`), which left its first file unread; `-t`'s folder attached or in a group
  (`cp -t/tmp/x a`, `mv -ft /tmp/x a`), and any option's value in a group (`mkdir -pm 755 x`); `find`'s `-fprint`,
  `-fprint0`, `-fprintf` and `-fls`; `git init`'s path and `--separate-git-dir`, with `--template`, `init.templateDir` and `GIT_TEMPLATE_DIR` asked, as their hooks reach every worktree; `sort -o`; and `busybox` and `toybox`,
  read as the command they run, with `--install` asked.
- A `$"…"` word reads as its `"…"`. A `$'…'` word holding a character code (`$'\x6fut'`, `$'\157'`), which can spell
  anything, leaves the command line unread, so the gate asks; one holding another escape (`$'a\nb'`) is known only
  when it runs, so it asks only where it names a command or a path.
- A Pi file tool's `file://` URL with no path on this machine (`file://host/x`, `file:///a%2Fb`) asks, where it threw
  and blocked the call with a poor reason.
- `ln -s ../a.ts sub`, where `sub` is already a folder, reads the target from `sub`, where `ln` makes the link: no
  ask for a link staying inside, and an ask for one through a folder link that lands outside. On a line of several
  commands the folder may be gone by then, so both readings must stay inside. `-T`, `-n` and BSD's `-F` read the last
  operand as the link itself, as `ln` does.
